# Optimization Modeling Core

## Use when

- The user gives a word problem, business process, paper scenario, or benchmark prompt and expects a formal optimization model.
- Solver code exists but the issue appears to be a missing or incorrect formulation.
- The task asks for a complete model, not only a heuristic, simulation, or data summary.

## Do not use when

- The task is purely about software plumbing, visualization, data cleaning, or report writing.
- The problem is already fully formulated and the user only asks for code translation into a specific solver; use the solver-specific skill as the primary guide.
- The request is exploratory and the user explicitly wants brainstorming without implementation.

## Model-first workflow

1. Restate the business decision in plain language.
2. Identify sets, indices, units, and time granularity.
3. Extract parameters from data files and confirm units.
4. Define decision variables with domains and business meaning.
5. Write the objective with every cost, reward, penalty, and service term.
6. Write constraints grouped by operational rule.
7. Check edge cases: missing eligibility, impossible demand, fixed commitments, and terminal-state requirements.
8. Only then implement code.

## Ambiguity handling

- If the brief is ambiguous but data and examples imply a convention, state the assumption and continue.
- If ambiguity changes feasibility, objective direction, or deliverable schema, ask before coding or implement the least risky interpretation with a clear note.
- If units conflict across files, normalize units explicitly before modeling.
- If a hard requirement conflicts with data, diagnose the conflict before adding slack variables.

## Formulation checklist

- Every row in an input table should either become a parameter, an eligibility rule, or be explicitly irrelevant.
- Every decision variable should appear in at least one binding constraint and usually in the objective.
- Demand balance should use the correct equality or inequality direction; do not weaken equality to `>=` unless surplus is genuinely allowed.
- Capacity constraints should include activation/open/setup binaries when the business says inactive resources cannot produce, ship, or serve.
- Shortage, backlog, overtime, outsourcing, and postponement variables need explicit cost and bounds.
- Multi-period models need state transition equations and initial/terminal states.
- If the user asks for explanation, describe the modeling logic in business terms after solving.

## Constraint boundary rules

- Hard constraints represent physical impossibility, policy mandates, legal requirements, or explicit benchmark feasibility rules.
- Soft constraints need penalty variables or objective terms; do not silently turn hard constraints into penalties.
- Service levels should specify numerator, denominator, eligible population, and time window.
- Fairness constraints should define the comparison group and whether unavailable resources count.
- Logical implications need both directions only when the business rule says equivalence, not merely implication.

## Objective boundary rules

- Confirm whether the problem minimizes cost, maximizes profit, maximizes service, or uses lexicographic priorities.
- Do not mix penalties with primary economics unless their scale is intentional.
- Include fixed costs only once per activated entity.
- Include revenue only for fulfilled demand or accepted jobs, not for unmet or canceled work.
- Keep reporting metrics separate from optimized objective terms unless the prompt explicitly optimizes them.

## Implementation expectations

- Use structured parsing for CSV/JSON instead of manual string manipulation.
- Keep solver code, solution export, and validation code clearly separated.
- For benchmark or task environments, read the provided brief before coding and follow the expected output schema exactly.
- When comparing two answers, diagnose concrete formulation differences and objective consequences, not only feasibility.
- Write exported solutions at the precision expected by the checker; avoid unnecessary rounding.
- Preserve the input schema and output schema unless the user asks to redesign the benchmark.

## Verification boundary

- Verify feasibility independently from solver status when an evaluator or checker exists.
- Recompute objective from exported artifacts, not only from in-memory solver expressions.
- For benchmark tasks, create at least one negative check for each newly added rule when practical.
- For paper or real-world tasks, separate what is directly supported by the source from synthetic or assumed data.

## Red flags

- Objective terms that are counted twice or charged at the wrong marginal rate.
- Binary variables not linked tightly enough to continuous activity.
- Time periods shifted by one index.
- Average or fairness constraints that ignore the denominator or eligibility set.
- Public prompt files that reveal solver-ready variables or formulas when the benchmark is meant to test modeling translation.
- A feasible solution that exploits missing eligibility, free disposal, negative cycles, or unbounded production.
- A model that reports optimality after a time limit, infeasible status, or missing incumbent.

# OR PySCIPOpt

## Use when

- The task asks for a Python optimization model using SCIP or `pyscipopt`.
- Existing solver code imports `pyscipopt`, sets SCIP parameters, writes `.lp`/`.mps`, or calls a SCIP-based checker.
- The user asks to run, debug, speed up, validate, or explain a SCIP-based solve.

## Do not use when

- The task only needs a mathematical formulation and no solver-specific code.
- The project clearly uses a different solver stack, such as Pyomo with CBC/HiGHS, OR-Tools CP-SAT, PuLP, CPLEX, or cvxpy, unless the user asks to port it to PySCIPOpt.
- The model is nonlinear or stochastic in a way that SCIP cannot handle directly; first decide whether it can be linearized or approximated.

## Environment rule

Use the Python environment specified by the user or the project. In this ORClaw workspace, the default solver environment is the `or` conda environment with PySCIPOpt available:

```bash
conda run -n or python <script.py>
```

If `pyscipopt` is missing, report the missing dependency, identify the command that failed, and try the project-specified environment before changing solver stacks.

## Workflow

1. Read the task brief and input files before coding.
2. Write the full mathematical model first: sets, parameters, decision variables, objective, and constraints.
3. Implement the model with explicit tuple keys and named constraints.
4. Solve with the selected Python command.
5. Export the solution using the exact schema required by the task.
6. Validate with the task checker or an independent recomputation of feasibility and objective.
7. If the solution is not accepted, diagnose whether the issue is formulation, data parsing, export formatting, tolerance, or evaluator mismatch before changing the objective or constraints.

## PySCIPOpt patterns

- Use `from pyscipopt import Model, quicksum`.
- Create sparse variable dictionaries explicitly, for example:

```python
x = {(i, j, t): model.addVar(vtype="B", name=f"x[{i},{j},{t}]") for i, j, t in keys}
```

- Use `quicksum(...)` for large linear expressions.
- Use `model.addCons(expr <= rhs, name="capacity[k,t]")` for constraints.
- Use `model.setObjective(expr, "minimize")` or `model.setObjective(expr, "maximize")`.
- Set reproducibility and limits with SCIP parameters:

```python
model.setParam("limits/gap", 0.0005)
model.setParam("limits/time", time_limit)
model.setParam("display/verblevel", 0)
```

- After `model.optimize()`, inspect `model.getStatus()` and only read values if a solution exists.
- Read variable values with `model.getVal(x[key])`, not `x[key].X`.
- Read objective and bound with `model.getObjVal()` and `model.getDualbound()`.
- Read relative gap with `model.getGap()` when available.

## Modeling hygiene

- Calibrate every big-M from data. If a tight M is not obvious, derive a bound and document it in a short comment.
- Keep feasibility checks, objective recomputation, and reference-optimality comparison separate.
- Do not round exported decision values unless the schema explicitly requires it.
- For benchmark work, treat the evaluator or checker as the scoring authority and the reference solver as a validation baseline.
- Keep solver logs or a concise solve summary when the user needs auditability.
- Avoid changing data to make a model feasible unless the task is explicitly to design or repair an instance.

## Debugging boundaries

- If a model is infeasible, inspect hard lower bounds, conservation equations, and mutually exclusive binary logic before relaxing constraints.
- If objective values differ, recompute each objective component from exported decisions.
- If runtime is high, first remove dominated variables, tighten big-M values, add eligibility filters, and check whether binaries are really necessary.
- If SCIP returns an incumbent with a gap, say so clearly; do not call it exact optimality unless the status and gap support that claim.
- If an evaluator rejects a solution that the model considers feasible, replay the rejected rule directly from the exported file before changing solver code.

## Useful commands

```bash
python -c "import pyscipopt; print(pyscipopt.__version__)"
conda run -n or python -c "import pyscipopt; print(pyscipopt.__version__)"
<python-command> <solver-script.py>
<python-command> <checker-script.py> --solution <solution-file> --env-dir <task-dir>
```

of terminals, depots, and retail or critical-use fueling points. The planning
team must decide regular inbound shipments from supply terminals to depots

policy that describes how each demand scenario would be served from the depots
and, if necessary, emergency spot-market carriers.

The operating goal is to minimize total cost while protecting service for
critical fuel users under distributional ambiguity. The checker evaluates the
regular inbound plan plus the scenario response costs using an ambiguity
stress rule: most weight follows the empirical scenario probabilities, but a
specified fraction of probability mass may concentrate on the most expensive
observed stress scenario. This rewards plans that do not look cheap only under
the average case.

You are planning a six-day regional fuel replenishment and response policy for

# Advanced MIP Patterns

## Use when

- The formulation needs logical implications, fixed charges, activation decisions, ordering, no-overlap, disjunctions, min/max, absolute values, tiers, route state, or resource calendars.
- A simple LP/MIP is producing unrealistic behavior because decisions are not linked tightly enough.
- The model is slow or infeasible and the likely cause is weak big-M logic, excessive pairwise variables, or missing state transitions.

## Do not use when

- A continuous LP is sufficient and adding binaries would not represent a real decision.
- The task is better handled by a specialized CP-SAT, constraint programming, nonlinear, or simulation method and the user did not require MIP.
- The user only needs a high-level explanation; do not introduce advanced constructs unless they clarify the actual model.

## General boundary rules

- Add binaries only for real yes/no choices, disjunctions, or nonconvex structure.
- Prefer the tightest formulation that matches the business rule; avoid decorative binaries.
- Use solver-native constructs when they improve clarity and are supported by the target environment.
- If a construct makes the model much slower, compare it with a simpler valid alternative before keeping it.

## Fixed charge and activation

- Use a binary `y` for whether an activity/resource is active.
- Link activity with a tight bound: `x <= U * y`.
- Add lower activation only when the business requires minimum use: `x >= L * y`.
- Charge fixed cost once through `fixed_cost * y`, not per unit.
- Do not force `y = 1` whenever `x = 0` unless the activity is mandatory.
- If there are startup/shutdown costs over time, separate active state from transition state.

## Logical rules

- Prefer solver-native indicator constraints for simple if-then rules when they keep the model clearer.
- If using big-M, derive M from data bounds and keep one M per rule family when possible.
- For either-or choices, use binaries whose sum is exactly one or at most one, matching the business rule.
- Distinguish implication (`A -> B`) from equivalence (`A <-> B`); the reverse direction often needs a separate constraint.
- For conditional capacity, link both activity and resource use to the condition.

## Min, max, absolute value

- For `z = max(a, b)`, add `z >= a`, `z >= b`, and objective pressure if minimizing z. Use binaries only when equality is needed without objective pressure.
- For absolute deviation `d = |x - target|`, add `d >= x - target` and `d >= target - x`.
- For service-level penalties, separate hard feasibility from soft penalty variables.
- For `min`, either transform with signs or add binaries when equality is not enforced by the objective.
- For ratio constraints, cross-multiply only when denominators are constant or safely bounded away from zero.

## Sequencing and no-overlap

- For jobs sharing a resource, use order binary `before[i,j]`.
- Typical pattern:
  - `start[j] >= end[i] - M * (1 - before[i,j])`
  - `start[i] >= end[j] - M * before[i,j]`
- Compute M from the scheduling horizon, not from an arbitrary large number.
- Include setup, cleanup, travel, rest, or turnover time in the correct side of the ordering constraint.
- Create pairwise order variables only for pairs that can share a resource or conflict.
- If time is discrete and the horizon is small, a time-indexed model may be cleaner than pairwise disjunctions.

## Piecewise and tiers

- Use solver-native piecewise-linear features for convex piecewise costs when suitable.
- For nonconvex tiers, use explicit segment variables and segment activation binaries.
- Ensure tier quantities sum to the original activity and each tier has its own upper bound.
- Distinguish incremental tiers from all-units tiers; their formulations and costs differ.
- Check whether discount tiers create nonconvex incentives that require binary selection.

## State and inventory logic

- State variables need initial conditions, transition equations, and terminal requirements if the business specifies them.
- Route or schedule state should be advanced in event order, not checked only row by row.
- Recovery, restock, cleaning, cooldown, maintenance, and rest rules often require cumulative state or last-event logic.
- If state can reset, model the reset trigger and its resource/time cost.

## Debugging advanced models

- First solve a relaxed or smaller instance and inspect whether the intended binaries activate.
- Add named constraints so IIS output points to business rules.
- If the reference solution is infeasible, replay the relevant state transitions manually before changing the evaluator.
- If the LP relaxation is very weak, inspect big-M values, missing lower/upper links, and symmetry.
- If the model is unexpectedly infeasible, test each advanced rule family on a tiny instance with a known feasible solution.

def build_model(data: dict, time_limit: float) -> tuple[Model, dict[str, dict], dict[str, float]]:
    model = Model("petroleum_terminal_dro_inventory")
    model.hideOutput()
    model.setParam("display/verblevel", 0)
    model.setParam("limits/gap", SCIP_GAP)
    model.setParam("limits/time", time_limit)

    config = data["config"]
    periods = data["periods"]
    scenarios = data["scenarios"]
    products = data["products"]
    depots = data["depots"]
    inbound_arcs = data["inbound_arcs"]
    outbound_arcs = data["outbound_arcs"]
    route_pairs = data["route_pairs"]
    station_products = data["active_station_products"]

    x = {}
    for period in periods:
        for terminal, depot, product in inbound_arcs:
            key = (period, terminal, depot, product)
            x[key] = model.addVar(
                lb=data["commitments"].get(key, 0.0),
                ub=data["inbound_cap"][(terminal, depot, product)],
                vtype="C",
                name=f"x[{period},{terminal},{depot},{product}]",
            )

    q = {}
    for scenario, period, depot, station, product in data["outbound_keys"]:
        eff_cap = data["route_eff_cap"][(scenario, period, depot, station, product)]
        q[(scenario, period, depot, station, product)] = model.addVar(
            lb=0.0,
            ub=eff_cap,
            vtype="C",
            name=f"q[{scenario},{period},{depot},{station},{product}]",
        )

    y = {}
    for scenario, period, depot, station in data["stop_keys"]:
        y[(scenario, period, depot, station)] = model.addVar(
            vtype="B",
            name=f"y[{scenario},{period},{depot},{station}]",

    depot_inventory = {}
    for scenario, period, depot, product in data["depot_inventory_keys"]:
        depot_inventory[(scenario, period, depot, product)] = model.addVar(
            lb=data["depot_reserve"][(depot, product)],
            ub=data["depot_cap"][(depot, product)],
            vtype="C",
            name=f"I[{scenario},{period},{depot},{product}]",
        )

    emergency = {}
    shortage = {}
    station_inventory = {}
    for scenario, period, station, product in data["station_keys"]:
        demand = data["demand"][(scenario, period, station, product)]
        floor = data["station_floor"][(station, product)]
        emergency[(scenario, period, station, product)] = model.addVar(
            lb=0.0,
            vtype="C",
            name=f"e[{scenario},{period},{station},{product}]",
        )
        shortage[(scenario, period, station, product)] = model.addVar(
            lb=0.0,
            ub=(1.0 - floor) * demand,
            vtype="C",
            name=f"u[{scenario},{period},{station},{product}]",
        )
        station_inventory[(scenario, period, station, product)] = model.addVar(
            lb=data["station_reserve"][(station, product)],
            ub=data["station_cap"][(station, product)],
            vtype="C",
            name=f"V[{scenario},{period},{station},{product}]",
        )

    scenario_cost = {scenario: model.addVar(lb=0.0, vtype="C", name=f"c[{scenario}]") for scenario in scenarios}
    worst_cost = model.addVar(lb=0.0, vtype="C", name="worst_cost")

    for period in periods:
        for terminal in data["terminals"]:
            for product in products:
                depots_for_arc = data["inbound_depots_by_tp"].get((terminal, product), [])
                if not depots_for_arc:
                    continue
                model.addCons(
                    quicksum(x[(period, terminal, depot, product)] for depot in depots_for_arc)
                    <= data["robust_terminal_cap"][(period, terminal, product)],
                    name=f"terminal_cap[{period},{terminal},{product}]",
                )

    for scenario in scenarios:
        for period_idx, period in enumerate(periods):
            prev_period = periods[period_idx - 1] if period_idx > 0 else None

            for depot in depots:
                for product in products:
                    inbound_terms = data["inbound_terminals_by_dp"].get((depot, product), [])
                    outbound_stations = data["outbound_stations_by_dp"].get((depot, product), [])
                    prev_inventory = (
                        data["depot_init"][(depot, product)]
                        if prev_period is None
                        else depot_inventory[(scenario, prev_period, depot, product)]
                    )
                    model.addCons(
                        depot_inventory[(scenario, period, depot, product)]
                        == prev_inventory
                        + quicksum(x[(period, terminal, depot, product)] for terminal in inbound_terms)
                        - quicksum(q[(scenario, period, depot, station, product)] for station in outbound_stations),
                        name=f"depot_balance[{scenario},{period},{depot},{product}]",
                    )
                    model.addCons(
                        quicksum(q[(scenario, period, depot, station, product)] for station in outbound_stations)
                        <= data["shift_cap"][(period, depot, product)],
                        name=f"shift_cap[{scenario},{period},{depot},{product}]",
                    )

                model.addCons(
                    quicksum(
                        q[(scenario, period, depot, station, product)]
                        for station, product in (
                            (station, product)
                            for station in data["stations"]
                            for product in data["outbound_products_by_pair"].get((depot, station), [])
                        )
                    )
                    <= data["fleet_cap"][(period, depot)],
                    name=f"fleet_cap[{scenario},{period},{depot}]",
                )
                model.addCons(
                    quicksum(y[(scenario, period, depot, station)] for station in data["stations"] if (depot, station) in data["route_pairs"])
                    <= data["fleet_stops"][(period, depot)],
                    name=f"fleet_stops[{scenario},{period},{depot}]",
                )

            for station, product in station_products:
                inbound_depots = data["outbound_depots_by_jp"][(station, product)]
                prev_inventory = (
                    data["station_init"][(station, product)]
                    if prev_period is None
                    else station_inventory[(scenario, prev_period, station, product)]
                )
                model.addCons(
                    station_inventory[(scenario, period, station, product)]
                    == prev_inventory
                    + quicksum(q[(scenario, period, depot, station, product)] for depot in inbound_depots)
                    + emergency[(scenario, period, station, product)]
                    - data["demand"][(scenario, period, station, product)]
                    + shortage[(scenario, period, station, product)],
                    name=f"station_balance[{scenario},{period},{station},{product}]",
                )

            for depot, station in route_pairs:
                products_on_pair = data["outbound_products_by_pair"][(depot, station)]
                for product in products_on_pair:
                    model.addCons(
                        q[(scenario, period, depot, station, product)]
                        <= data["route_eff_cap"][(scenario, period, depot, station, product)] * y[(scenario, period, depot, station)],
                        name=f"route_link[{scenario},{period},{depot},{station},{product}]",
                    )
                model.addCons(
                    quicksum(q[(scenario, period, depot, station, product)] for product in products_on_pair)
                    <= config["max_kl_per_active_stop"] * y[(scenario, period, depot, station)],
                    name=f"stop_cap[{scenario},{period},{depot},{station}]",
                )

        for product in products:
            stations_for_product = [station for station, product2 in station_products if product2 == product]
            model.addCons(
                quicksum(emergency[(scenario, period, station, product)] for period in periods for station in stations_for_product)
                <= data["emergency_cap"][(scenario, product)],
                name=f"emergency_cap[{scenario},{product}]",
            )

        scenario_expr = (
            quicksum(
                data["outbound_unit_cost"][(depot, station, product)] * q[(scenario, period, depot, station, product)]
                for period in periods
                for depot, station, product in outbound_arcs
            )
            + config["active_stop_cost"]
            * quicksum(y[(scenario, period, depot, station)] for period in periods for depot, station in route_pairs)
            + quicksum(
                data["product_params"][product]["emergency_cost"] * emergency[(scenario, period, station, product)]
                for period in periods
                for station, product in station_products
            )
            + quicksum(
                data["product_params"][product]["shortage_penalty"] * shortage[(scenario, period, station, product)]
                for period in periods
                for station, product in station_products
            )
            + quicksum(
                data["product_params"][product]["holding_depot"] * depot_inventory[(scenario, period, depot, product)]
                for period in periods
                for depot in depots
                for product in products
            )
            + quicksum(
                data["product_params"][product]["holding_station"] * station_inventory[(scenario, period, station, product)]
                for period in periods
                for station, product in station_products
            )
        )
        model.addCons(scenario_cost[scenario] == scenario_expr, name=f"scenario_cost[{scenario}]")
        model.addCons(worst_cost >= scenario_cost[scenario], name=f"worst_cost_lb[{scenario}]")

    inbound_cost_expr = quicksum(
        data["inbound_unit_cost"][(terminal, depot, product)] * x[(period, terminal, depot, product)]
        for period, terminal, depot, product in data["inbound_keys"]
    )

    model.setObjective(
        inbound_cost_expr
        + (1.0 - config["ambiguity_worst_case_weight"])
        * quicksum(data["scenario_prob"][scenario] * scenario_cost[scenario] for scenario in scenarios)
        + config["ambiguity_worst_case_weight"] * worst_cost,
        "minimize",
    )

    vars_by_name = {
        "x": x,
        "q": q,
        "y": y,
        "depot_inventory": depot_inventory,
        "emergency": emergency,
        "shortage": shortage,
        "station_inventory": station_inventory,
        "scenario_cost": scenario_cost,
        "worst_cost": {"worst_cost": worst_cost},
    }
    return model, vars_by_name, {"time_limit": time_limit}

def append_log(
    command: str,
    time_limit: float,
    build_seconds: float,
    solve_seconds: float,
    status: str,
    nsols: int,
    incumbent_obj: float | None,
    dualbound: float | None,
    gap: float | None,
    audit: dict | None,
) -> None:
    lines = []
    if not LOG_PATH.exists():
        lines.append("# Solve Log\n")
    lines.append(f"\n## Run {time.strftime('%Y-%m-%d %H:%M:%S')}\n")
    lines.append(f"- Command: `{command}`\n")
    lines.append(f"- Time limit (s): `{time_limit:.2f}`\n")
    lines.append(f"- Build time (s): `{build_seconds:.2f}`\n")

    lines.append(f"- SCIP status: `{status}`\n")
    lines.append(f"- Incumbent count: `{nsols}`\n")
    if incumbent_obj is not None:
        lines.append(f"- Solver incumbent objective: `{incumbent_obj:.6f}`\n")
    if dualbound is not None:
        lines.append(f"- Solver dual bound: `{dualbound:.6f}`\n")
    if gap is not None:
        lines.append(f"- Solver relative gap: `{gap:.6f}`\n")
    if audit is None:
        lines.append("- Validation: not run\n")
    else:
        lines.append(f"- Validation feasible: `{audit['feasible']}`\n")
        lines.append(f"- Validation max theta: `{audit['max_theta']:.6e}`\n")
        lines.append(f"- Validation violated groups: `{audit['violated_groups']}`\n")

        lines.append(f"- Validation worst scenario cost: `{audit['worst_cost']:.6f}`\n")
        if audit["messages"]:
            lines.append("- Validation notes:\n")
            for message in audit["messages"]:
                lines.append(f"  - {message}\n")
            if audit["num_messages"] > len(audit["messages"]):
                lines.append(f"  - ... {audit['num_messages'] - len(audit['messages'])} more messages omitted\n")

    with LOG_PATH.open("a") as handle:
        handle.writelines(lines)

def apply_mip_start(model: Model, vars_by_name: dict[str, dict], state: dict[str, dict]) -> bool:
    sol = model.createSol()
    for family in ("x", "q", "y", "depot_inventory", "emergency", "shortage", "station_inventory", "reserve_binding", "scenario_cost", "worst_cost"):
        values = state.get(family, {})
        for key, var in vars_by_name[family].items():
            if key in values:
                model.setSolVal(sol, var, float(values[key]))
    return bool(model.trySol(sol, printreason=False, completely=True, checkbounds=True, checkintegrality=True, checklprows=False, free=True))

# Advanced MIP Patterns

## Use when

- The formulation needs logical implications, fixed charges, activation decisions, ordering, no-overlap, disjunctions, min/max, absolute values, tiers, route state, or resource calendars.
- A simple LP/MIP is producing unrealistic behavior because decisions are not linked tightly enough.
- The model is slow or infeasible and the likely cause is weak big-M logic, excessive pairwise variables, or missing state transitions.

## Do not use when

- A continuous LP is sufficient and adding binaries would not represent a real decision.
- The task is better handled by a specialized CP-SAT, constraint programming, nonlinear, or simulation method and the user did not require MIP.
- The user only needs a high-level explanation; do not introduce advanced constructs unless they clarify the actual model.

## General boundary rules

- Add binaries only for real yes/no choices, disjunctions, or nonconvex structure.
- Prefer the tightest formulation that matches the business rule; avoid decorative binaries.
- Use solver-native constructs when they improve clarity and are supported by the target environment.
- If a construct makes the model much slower, compare it with a simpler valid alternative before keeping it.

## Fixed charge and activation

- Use a binary `y` for whether an activity/resource is active.
- Link activity with a tight bound: `x <= U * y`.
- Add lower activation only when the business requires minimum use: `x >= L * y`.
- Charge fixed cost once through `fixed_cost * y`, not per unit.
- Do not force `y = 1` whenever `x = 0` unless the activity is mandatory.
- If there are startup/shutdown costs over time, separate active state from transition state.

## Logical rules

- Prefer solver-native indicator constraints for simple if-then rules when they keep the model clearer.
- If using big-M, derive M from data bounds and keep one M per rule family when possible.
- For either-or choices, use binaries whose sum is exactly one or at most one, matching the business rule.
- Distinguish implication (`A -> B`) from equivalence (`A <-> B`); the reverse direction often needs a separate constraint.
- For conditional capacity, link both activity and resource use to the condition.

## Min, max, absolute value

- For `z = max(a, b)`, add `z >= a`, `z >= b`, and objective pressure if minimizing z. Use binaries only when equality is needed without objective pressure.
- For absolute deviation `d = |x - target|`, add `d >= x - target` and `d >= target - x`.
- For service-level penalties, separate hard feasibility from soft penalty variables.
- For `min`, either transform with signs or add binaries when equality is not enforced by the objective.
- For ratio constraints, cross-multiply only when denominators are constant or safely bounded away from zero.

## Sequencing and no-overlap

- For jobs sharing a resource, use order binary `before[i,j]`.
- Typical pattern:
  - `start[j] >= end[i] - M * (1 - before[i,j])`
  - `start[i] >= end[j] - M * before[i,j]`
- Compute M from the scheduling horizon, not from an arbitrary large number.
- Include setup, cleanup, travel, rest, or turnover time in the correct side of the ordering constraint.
- Create pairwise order variables only for pairs that can share a resource or conflict.
- If time is discrete and the horizon is small, a time-indexed model may be cleaner than pairwise disjunctions.

## Piecewise and tiers

- Use solver-native piecewise-linear features for convex piecewise costs when suitable.
- For nonconvex tiers, use explicit segment variables and segment activation binaries.
- Ensure tier quantities sum to the original activity and each tier has its own upper bound.
- Distinguish incremental tiers from all-units tiers; their formulations and costs differ.
- Check whether discount tiers create nonconvex incentives that require binary selection.

## State and inventory logic

- State variables need initial conditions, transition equations, and terminal requirements if the business specifies them.
- Route or schedule state should be advanced in event order, not checked only row by row.
- Recovery, restock, cleaning, cooldown, maintenance, and rest rules often require cumulative state or last-event logic.
- If state can reset, model the reset trigger and its resource/time cost.

## Debugging advanced models

- First solve a relaxed or smaller instance and inspect whether the intended binaries activate.
- Add named constraints so IIS output points to business rules.
- If the reference solution is infeasible, replay the relevant state transitions manually before changing the evaluator.
- If the LP relaxation is very weak, inspect big-M values, missing lower/upper links, and symmetry.
- If the model is unexpectedly infeasible, test each advanced rule family on a tiny instance with a known feasible solution.

                model.addCons(
                    quicksum(y[(scenario, period, depot, station)] for station in data["stations"] if (depot, station) in data["route_pair_set"])

def extract_solution(model: Model, vars_by_name: dict[str, dict], data: dict) -> list[dict[str, str]]:
    if model.getNSols() <= 0 or model.getBestSol() is None:
        raise RuntimeError("SCIP finished without an incumbent solution")

    best_sol = model.getBestSol()
    rows: list[tuple[str, str, str, str, str, str, float]] = []

    for key, var in vars_by_name["x"].items():
        value = model.getSolVal(best_sol, var)
        if value > EXPORT_EPS:
            period, terminal, depot, product = key
            rows.append(("inbound", "", period, terminal, depot, product, value))

    for key, var in vars_by_name["q"].items():
        value = model.getSolVal(best_sol, var)
        if value > EXPORT_EPS:
            scenario, period, depot, station, product = key
            rows.append(("delivery", scenario, period, depot, station, product, value))

    for key, var in vars_by_name["emergency"].items():
        value = model.getSolVal(best_sol, var)
        if value > EXPORT_EPS:
            scenario, period, station, product = key
            rows.append(("emergency", scenario, period, "EMERGENCY", station, product, value))

    row_order = {"inbound": 0, "delivery": 1, "emergency": 2}
    rows.sort(key=lambda row: (row_order[row[0]], row[1], data["period_index"][row[2]], row[3], row[4], row[5]))

    export_rows = []
    for row_type, scenario, period, origin, destination, product, quantity in rows:
        export_rows.append(
            {
                "row_type": row_type,
                "scenario_id": scenario,
                "period_id": period,
                "origin_id": origin,
                "destination_id": destination,
                "product_id": product,
                "quantity": format_qty(quantity),
            }
        )
    return export_rows


def write_solution(rows: list[dict[str, str]], path: Path) -> None:
    fieldnames = ["row_type", "scenario_id", "period_id", "origin_id", "destination_id", "product_id", "quantity"]
    with path.open("w", newline="") as handle:

        writer.writerows(rows)


def audit_solution(data: dict, path: Path) -> dict:
    expected_fields = ["row_type", "scenario_id", "period_id", "origin_id", "destination_id", "product_id", "quantity"]
    inbound = defaultdict(float)
    delivery = defaultdict(float)
    emergency = defaultdict(float)

    violated_groups: set[str] = set()
    messages: list[str] = []
    max_theta = 0.0

    def record_violation(group: str, message: str, magnitude: float, scale: float) -> None:
        nonlocal max_theta
        violated_groups.add(group)
        theta = max(0.0, magnitude) / max(1.0, abs(scale))
        max_theta = max(max_theta, theta)
        messages.append(message)

    with path.open(newline="") as handle:
        reader = csv.DictReader(handle)
        if reader.fieldnames != expected_fields:
            record_violation("schema", f"Unexpected columns: {reader.fieldnames}", 1.0, 1.0)
        for idx, row in enumerate(reader, start=2):
            try:
                quantity = float(row["quantity"])
            except Exception:
                record_violation("schema", f"Row {idx}: invalid quantity {row['quantity']!r}", 1.0, 1.0)
                continue
            if not math.isfinite(quantity) or quantity < -CHECK_TOL:
                record_violation("nonnegativity", f"Row {idx}: invalid quantity {quantity}", max(0.0, -quantity), 1.0)
                continue
            quantity = max(0.0, quantity)
            row_type = row["row_type"]
            period = row["period_id"]
            product = row["product_id"]
            scenario = row["scenario_id"]
            origin = row["origin_id"]
            destination = row["destination_id"]

            if period not in data["period_index"]:
                record_violation("schema", f"Row {idx}: invalid period {period}", 1.0, 1.0)
                continue
            if product not in data["products"]:
                record_violation("schema", f"Row {idx}: invalid product {product}", 1.0, 1.0)
                continue

            if row_type == "inbound":
                if scenario not in ("", None):
                    record_violation("schema", f"Row {idx}: inbound row must have blank scenario_id", 1.0, 1.0)
                key = (period, origin, destination, product)
                if (origin, destination, product) not in data["inbound_arc_set"]:
                    record_violation("schema", f"Row {idx}: invalid inbound lane {key}", 1.0, 1.0)
                    continue
                inbound[key] += quantity
            elif row_type == "delivery":
                if scenario not in data["scenarios"]:
                    record_violation("schema", f"Row {idx}: invalid scenario {scenario}", 1.0, 1.0)
                    continue
                key = (scenario, period, origin, destination, product)
                if (origin, destination, product) not in data["outbound_arc_set"]:
                    record_violation("schema", f"Row {idx}: invalid delivery lane {key}", 1.0, 1.0)
                    continue
                delivery[key] += quantity
            elif row_type == "emergency":
                if scenario not in data["scenarios"]:
                    record_violation("schema", f"Row {idx}: invalid scenario {scenario}", 1.0, 1.0)
                    continue
                if origin != "EMERGENCY":
                    record_violation("schema", f"Row {idx}: emergency origin must be EMERGENCY", 1.0, 1.0)
                    continue
                if (destination, product) not in data["active_station_products"]:
                    record_violation("schema", f"Row {idx}: invalid emergency station-product {(destination, product)}", 1.0, 1.0)
                    continue
                emergency[(scenario, period, destination, product)] += quantity
            else:
                record_violation("schema", f"Row {idx}: invalid row_type {row_type}", 1.0, 1.0)

    for period, terminal, depot, product in data["inbound_keys"]:
        quantity = inbound.get((period, terminal, depot, product), 0.0)
        cap = data["inbound_cap"][(terminal, depot, product)]
        commit = data["commitments"].get((period, terminal, depot, product), 0.0)
        if quantity > cap + CHECK_TOL:
            record_violation(
                "inbound_lane_cap",
                f"Inbound {period, terminal, depot, product} exceeds lane cap: {quantity:.6f} > {cap:.6f}",
                quantity - cap,
                cap,
            )
        if quantity + CHECK_TOL < commit:
            record_violation(
                "commitment",
                f"Inbound {period, terminal, depot, product} misses commitment: {quantity:.6f} < {commit:.6f}",
                commit - quantity,
                commit,
            )

    for period in data["periods"]:
        for terminal in data["terminals"]:
            for product in data["products"]:
                depots_for_arc = data["inbound_depots_by_tp"].get((terminal, product), [])
                if not depots_for_arc:
                    continue
                total = sum(inbound.get((period, terminal, depot, product), 0.0) for depot in depots_for_arc)
                cap = data["robust_terminal_cap"][(period, terminal, product)]
                if total > cap + CHECK_TOL:
                    record_violation(
                        "terminal_capacity",
                        f"Terminal cap {period, terminal, product} exceeded: {total:.6f} > {cap:.6f}",
                        total - cap,
                        cap,
                    )

    inbound_cost = 0.0
    for period, terminal, depot, product in data["inbound_keys"]:
        inbound_cost += data["inbound_unit_cost"][(terminal, depot, product)] * inbound.get((period, terminal, depot, product), 0.0)

    scenario_costs: dict[str, float] = {}

    for scenario in data["scenarios"]:
        depot_prev = {key: data["depot_init"][key] for key in data["depot_products"]}
        station_prev = {key: data["station_init"][key] for key in data["active_station_products"]}
        scenario_cost = 0.0
        emergency_used = defaultdict(float)

        for period in data["periods"]:
            active_stop_count = defaultdict(int)
            fleet_outbound = defaultdict(float)
            shift_outbound = defaultdict(float)
            pair_totals = defaultdict(float)
            depot_outbound = defaultdict(float)
            station_inbound = defaultdict(float)

            for depot, station, product in data["outbound_arcs"]:
                qty = delivery.get((scenario, period, depot, station, product), 0.0)
                cap = data["route_eff_cap"][(scenario, period, depot, station, product)]
                if qty > cap + CHECK_TOL:
                    record_violation(
                        "delivery_lane_cap",
                        f"Delivery cap {scenario, period, depot, station, product} exceeded: {qty:.6f} > {cap:.6f}",
                        qty - cap,
                        cap,
                    )
                depot_outbound[(depot, product)] += qty
                fleet_outbound[depot] += qty
                shift_outbound[(depot, product)] += qty
                pair_totals[(depot, station)] += qty
                station_inbound[(station, product)] += qty
                scenario_cost += data["outbound_unit_cost"][(depot, station, product)] * qty

            for depot, station in data["route_pairs"]:
                total = pair_totals[(depot, station)]
                if total > CHECK_TOL:
                    active_stop_count[depot] += 1
                    scenario_cost += data["config"]["active_stop_cost"]
                if total > data["config"]["max_kl_per_active_stop"] + CHECK_TOL:
                    record_violation(
                        "stop_cap",
                        f"Stop cap {scenario, period, depot, station} exceeded: {total:.6f} > {data['config']['max_kl_per_active_stop']:.6f}",
                        total - data["config"]["max_kl_per_active_stop"],
                        data["config"]["max_kl_per_active_stop"],
                    )

            for depot in data["depots"]:
                if fleet_outbound[depot] > data["fleet_cap"][(period, depot)] + CHECK_TOL:
                    record_violation(
                        "fleet_cap",
                        f"Fleet cap {scenario, period, depot} exceeded: {fleet_outbound[depot]:.6f} > {data['fleet_cap'][(period, depot)]:.6f}",
                        fleet_outbound[depot] - data["fleet_cap"][(period, depot)],
                        data["fleet_cap"][(period, depot)],
                    )
                if active_stop_count[depot] > data["fleet_stops"][(period, depot)]:
                    record_violation(
                        "fleet_stops",
                        f"Stop limit {scenario, period, depot} exceeded: {active_stop_count[depot]} > {data['fleet_stops'][(period, depot)]}",
                        active_stop_count[depot] - data["fleet_stops"][(period, depot)],
                        data["fleet_stops"][(period, depot)],
                    )
                for product in data["products"]:
                    if shift_outbound[(depot, product)] > data["shift_cap"][(period, depot, product)] + CHECK_TOL:
                        record_violation(
                            "shift_cap",
                            f"Shift cap {scenario, period, depot, product} exceeded: {shift_outbound[(depot, product)]:.6f} > {data['shift_cap'][(period, depot, product)]:.6f}",
                            shift_outbound[(depot, product)] - data["shift_cap"][(period, depot, product)],
                            data["shift_cap"][(period, depot, product)],
                        )

                    end_inventory = depot_prev[(depot, product)] + sum(
                        inbound.get((period, terminal, depot, product), 0.0)
                        for terminal in data["inbound_terminals_by_dp"].get((depot, product), [])
                    ) - depot_outbound[(depot, product)]
                    if end_inventory < data["depot_reserve"][(depot, product)] - CHECK_TOL:
                        record_violation(
                            "depot_reserve",
                            f"Depot reserve {scenario, period, depot, product} violated: {end_inventory:.6f} < {data['depot_reserve'][(depot, product)]:.6f}",
                            data["depot_reserve"][(depot, product)] - end_inventory,
                            data["depot_reserve"][(depot, product)],
                        )
                    if end_inventory > data["depot_cap"][(depot, product)] + CHECK_TOL:
                        record_violation(
                            "depot_capacity",
                            f"Depot capacity {scenario, period, depot, product} exceeded: {end_inventory:.6f} > {data['depot_cap'][(depot, product)]:.6f}",
                            end_inventory - data["depot_cap"][(depot, product)],
                            data["depot_cap"][(depot, product)],
                        )
                    depot_prev[(depot, product)] = end_inventory
                    scenario_cost += data["product_params"][product]["holding_depot"] * end_inventory

            for station, product in data["active_station_products"]:
                em_qty = emergency.get((scenario, period, station, product), 0.0)
                emergency_used[product] += em_qty
                scenario_cost += data["product_params"][product]["emergency_cost"] * em_qty
                available = station_prev[(station, product)] + station_inbound[(station, product)] + em_qty
                reserve = data["station_reserve"][(station, product)]
                demand = data["demand"][(scenario, period, station, product)]
                shortage = max(0.0, demand + reserve - available)
                max_shortage = (1.0 - data["station_floor"][(station, product)]) * demand
                if shortage > max_shortage + CHECK_TOL:
                    record_violation(
                        "service_floor",
                        f"Service floor {scenario, period, station, product} violated: shortage {shortage:.6f} > {max_shortage:.6f}",
                        shortage - max_shortage,
                        max_shortage if max_shortage > 0 else 1.0,
                    )
                if shortage > demand + CHECK_TOL:
                    record_violation(
                        "station_balance",
                        f"Station balance impossible at {scenario, period, station, product}: implied shortage {shortage:.6f} exceeds demand {demand:.6f}",
                        shortage - demand,
                        demand if demand > 0 else 1.0,
                    )
                end_inventory = available - demand + shortage
                if end_inventory < reserve - CHECK_TOL:
                    record_violation(
                        "station_reserve",
                        f"Station reserve {scenario, period, station, product} violated: {end_inventory:.6f} < {reserve:.6f}",
                        reserve - end_inventory,
                        reserve,
                    )
                if end_inventory > data["station_cap"][(station, product)] + CHECK_TOL:
                    record_violation(

                        f"Station capacity {scenario, period, station, product} exceeded: {end_inventory:.6f} > {data['station_cap'][(station, product)]:.6f}",
                        end_inventory - data["station_cap"][(station, product)],
                        data["station_cap"][(station, product)],
                    )
                station_prev[(station, product)] = end_inventory
                scenario_cost += data["product_params"][product]["shortage_penalty"] * shortage

                    used - cap,

        scenario_costs[scenario] = scenario_cost

    worst_cost = max(scenario_costs.values()) if scenario_costs else 0.0
    expected_cost = sum(data["scenario_prob"][scenario] * scenario_costs[scenario] for scenario in data["scenarios"])
    total_objective = inbound_cost + (1.0 - data["config"]["ambiguity_worst_case_weight"]) * expected_cost + data["config"]["ambiguity_worst_case_weight"] * worst_cost

    return {
        "feasible": not violated_groups,
        "max_theta": max_theta,
        "violated_groups": sorted(violated_groups),
        "messages": messages[:50],
        "num_messages": len(messages),
        "num_rows": sum(1 for _ in path.open()) - 1,
        "inbound_cost": inbound_cost,
        "scenario_costs": scenario_costs,
        "worst_cost": worst_cost,
        "expected_cost": expected_cost,
        "objective": total_objective,
    }


def append_log(
    command: str,
    time_limit: float,
    build_seconds: float,
    solve_seconds: float,
    status: str,
    nsols: int,
    incumbent_obj: float | None,
    dualbound: float | None,
    gap: float | None,
    audit: dict | None,
) -> None:
    lines = []
    if not LOG_PATH.exists():
        lines.append("# Solve Log\n")
    lines.append(f"\n## Run {time.strftime('%Y-%m-%d %H:%M:%S')}\n")
    lines.append(f"- Command: `{command}`\n")
    lines.append(f"- Time limit (s): `{time_limit:.2f}`\n")
    lines.append(f"- Build time (s): `{build_seconds:.2f}`\n")
    lines.append(f"- Solve time (s): `{solve_seconds:.2f}`\n")
    lines.append(f"- SCIP status: `{status}`\n")
    lines.append(f"- Incumbent count: `{nsols}`\n")
    if incumbent_obj is not None:
        lines.append(f"- Solver incumbent objective: `{incumbent_obj:.6f}`\n")
    if dualbound is not None:
        lines.append(f"- Solver dual bound: `{dualbound:.6f}`\n")
    if gap is not None:
        lines.append(f"- Solver relative gap: `{gap:.6f}`\n")
    if audit is None:
        lines.append("- Validation: not run\n")
    else:
        lines.append(f"- Validation feasible: `{audit['feasible']}`\n")
        lines.append(f"- Validation max theta: `{audit['max_theta']:.6e}`\n")
        lines.append(f"- Validation violated groups: `{audit['violated_groups']}`\n")
        lines.append(f"- Validation objective: `{audit['objective']:.6f}`\n")
        lines.append(f"- Validation expected scenario cost: `{audit['expected_cost']:.6f}`\n")
        lines.append(f"- Validation worst scenario cost: `{audit['worst_cost']:.6f}`\n")
        if audit["messages"]:
            lines.append("- Validation notes:\n")
            for message in audit["messages"]:
                lines.append(f"  - {message}\n")
            if audit["num_messages"] > len(audit["messages"]):
                lines.append(f"  - ... {audit['num_messages'] - len(audit['messages'])} more messages omitted\n")

    with LOG_PATH.open("a") as handle:
        handle.writelines(lines)
